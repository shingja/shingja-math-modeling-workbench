## 一、检索流程

```text
明确要支撑的论断（一句话）
  → 构造关键词：核心概念 × 方法名 × 数据类型（中英各一组）
  → 双引擎并行：OpenAlex（元数据权威）+ AnySearch（覆盖广）
  → 交叉核验：DOI 或题名必须双源一致
  → 去重与分层：原理性文献 / 方法性文献 / 应用性文献各取所需
  → 格式化：按当届要求（CUMCM→GB/T 7714；MCM→编号制）
  → 死链与字段检查 → 入库
```

## 二、命令

```bash
python tools/paper_search/scripts/hybrid_scholar.py \
  --query "robust optimization vehicle routing" \
  --limit 10 --json
```

- OpenAlex 建议提供礼貌池邮箱；AnySearch 需要密钥时设置环境变量。
- 默认双引擎同跑；单引擎参数只用于诊断，不得作为正式检索依据。

## 三、核验规则（每条文献都要过）

| 检查 | 不通过的处理 |
|---|---|
| DOI 可解析 | 换源重查；查不到就**弃用**，不得"估一个" |
| 题名与作者一致 | 以 OpenAlex/Crossref 元数据为准 |
| 年份、卷期、页码齐全 | 缺项补齐后才写入参考文献 |
| 与论断相关 | 只做"背景"用途的文献不得写成"证明" |
| 未被撤稿 | 检查撤稿状态 |

## 四、红线

- ❌ 编造文献、DOI、页码（一次即为致命问题，直接触发返工）。
- ❌ 引用自己没读过的文献的具体结论。
- ❌ 用搜索到的"他人解题方案"替代自己的建模论证而不标注来源与差异。
- ⚠️ 竞赛期间的全网检索：赛题级讨论可以搜（用于覆盖检查与方案对标），**但必须遵守当届规则**；引用他人方案必须在论文/声明中如实标注（见 `protocols/external_search_protocol.md`，只检不禁 + 声明义务）。

## 五、交付物

- `references_verified.md`：每条文献的检索来源、核验结果、用途（支撑哪句论断）。
- 检索记录留档（关键词、时间、引擎、原始返回），供复现与答辩质询。
