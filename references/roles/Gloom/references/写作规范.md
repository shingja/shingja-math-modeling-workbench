- 术语和符号严格服从 `术语表格.md`。
- 每段围绕一个明确论点，先给事实或推理，再解释其含义。
- 数值、单位、公式、图号、表号和引用前后一致。
- 不使用”专家认为””效果显著”等无来源表述。
- 不用宣传性语言代替证据；创新点必须对应具体方法、实现和验证。
- 不虚构数据、实验、文献或官方要求。
- **内部参考与正式引用分离**：`LOCAL_TEXTBOOK_ROOT`（《各类常用数学模型》）和 `LOCAL_ALGO_ROOT`（算法资料）中的教材、代码、培训材料仅供 Skill 内部参考理论依据和实现细节，**不得作为参考文献列入论文**。论文参考文献必须通过 `tools/paper_search` 检索正式出版的期刊论文、学术专著（含 ISBN）或官方标准文档，每条引用可追溯至 DOI 或原始出版页面。
- 正文中提及模型原理时引用正式文献（如"[1] 邓聚龙. 灰色控制系统. 华中理工大学出版社, 1993."），而非引用内部教材。
- 两个模型得到相近结论时，如有比较价值，可如实保留并解释。
- 中文或英文表达服从目标竞赛和用户要求。

## 一等奖论文写作特征

以下模式提炼自 2023-2025 年国赛一等奖论文，作为写作质量参考。

### 摘要写作

- 摘要直接给出每个子问题的最优数值结果，不写”效果良好””明显改善”等空泛表述
- 结果搭配具体数字：误差率、精度百分比、缩短的距离、节省的成本等
- 最后一两句说明验证方式：灵敏度分析、对比实验、蒙特卡洛验证等
- 不使用”本文首次提出””填补空白”等夸大表述

### 正文写作

- 问题重述用自己的语言转述题目，不直接复制题目原文
- 模型假设逐条编号，每条说明假设的依据或合理性
- 符号说明以表格呈现，符号→含义→单位三列
- 建模过程按”思路→公式→求解→结果→分析”展开，不跳步
- 每个图的引用必须有文字分析，不只是”如图X所示”
- 灵敏度分析的参数变化范围必须说明选择依据
- 模型评价的局限性必须具体，不写”模型有一定局限性”这种空话

### 数值表达

- 保留适当小数位（通常 3-4 位有效数字）
- 百分比保留 1-2 位小数
- 大数使用科学计数法或适当单位
- p 值报告精确数值（如 p = 0.032），不只写 p < 0.05

## 数值来源规范 (与 S7 result_claim_bind 联动) (v3.0.0-s8 新增)

**核心原则：论文中所有数值必须从 `results/results.json` 提取，禁止手动输入数值。**

工作流：
1. Tide跑完 → 生成 `results/results.json`
2. 调用 `tools/result_claim_bind.m --bind` → 生成 `.bind_hash`
3. 调用 `tools/generate_paper_numbers.m` → 生成 `results/auto_numbers.tex`
4. LaTeX 论文中用 `\input{results/auto_numbers.tex}` 引用，然后用 `\result方案A得分` 等命令
5. 编译前调用 `result_claim_bind --verify` → 必须通过
6. JSON 变更 → 重跑步骤 2-5

**禁止行为**:
- 在 LaTeX/Word 正文中直接写数字（如 "得分为 0.8234"）
- 代码和论文数值不一致（C1 门禁的 D3 维度会检测）
