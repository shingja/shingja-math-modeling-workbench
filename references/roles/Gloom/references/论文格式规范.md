## 实测格式基线引用

> 完整实测数据(样例提交版论文 docx 逐项反解 + CUMCM 2026 官方规范核对)见: `../../../lessons/论文格式基线_CUMCM规范与实测.md`。该文件含: ①样例每项格式的实测值与 styles.xml/numbering.xml 依据 ②可直接复制的"三线表1"样式 XML 与"图名/表注/参考文献"段落样式定义 ③CUMCM 2026 官方硬约束核对表 ④国赛 Word 构建检查单(21 项)。**任何新竞赛论文生成前, 先读该基线 + 当届官方规范两者。**

关键规格速览(实测自样例提交版 docx + 渲染 PDF):

- 页面: A4, 四边页边距 2.5cm, 页眉距 1.5cm/页脚距 1.8cm, 文档网格行距 15.6pt; 页码=页脚居中 PAGE 域 9pt 从 1 起; 无目录、页眉为空; 3 节(摘要/正文/附录)。
- 标题: 主标题 16pt 加粗居中; H1 黑体 14pt 加粗**居中**, 自动编号"一、"; H2/H3 加粗左对齐, 自动编号"1.1"/"1.1.1"。**实测缺陷: 样例的 H2/H3 样式只设了 ascii=黑体, 中文实渲染为宋体 — 生成时必须同时设 eastAsia=黑体。**
- 正文: 宋体/Times New Roman, 两端对齐, 首行缩进 2 字符(firstLineChars=200), 行距贴 15.6pt 网格(样例实测字号 10pt, 偏小; 常规规范用 12pt)。
- 摘要页: 主标题→"摘 要"→摘要正文→"关键词:"(黑体 12pt 加粗)+内容, 单独成页。
- 图注: 样式"图名", **图下方**, 居中加粗, 全文连续"图N"; 表注: 样式"表注", **表上方**, 9pt 加粗, "表N"。均为自动编号(lvlText="表%7"/"%7图%1" 技巧, 见基线文件)。
- 三线表: 表格样式"三线表1" — 顶/底线 1.5pt(sz=12), 表头下线 0.5pt(sz=4), 无竖线; 单元格"表格文字"9pt 居中; 15/15 表全用此样式。
- 公式: OMML 原生 Cambria Math; 显示公式不挂编号, 正文引用按章"式(6-1)"。
- 参考文献: GB/T 7714 顺序编码制, 自动编号"[n]", 标题用 Subtitle 样式(16pt 加粗居中); AI 工具列为最后一条。
- 附录代码: Courier New 9pt, 行距固定 12pt, 0.75pt 左右边框代码框 + 行号。

## 唯一权威来源

论文内容结构与格式必须遵循目标竞赛当届官方规则和官方模板。常用官方入口：

- 全国大学生数学建模竞赛：`http://www.mcm.edu.cn/`
- CUMCM 2026 论文格式规范：团队资料文件夹中的 `全国大学生数学建模竞赛论文格式规范（2026版）.pdf`
- MCM/ICM：`https://www.comap.com/contests/mcm-icm`

## 国赛一等奖论文格式特征（基于 2023-2025 获奖论文分析）

以下模式来自往年国赛一等奖论文分析，作为排版质量参考。当届官方规则优先于以下任何模式。

### 整体结构

获奖论文通常采用以下结构（以 CUMCM 为例）：

1. 摘要页（单独一页，含关键词）
2. 问题重述（1-2 页）
3. 问题分析（0.5-1 页，说明建模思路和选模依据）
4. 模型假设与符号说明（1-2 页，符号以表格列出）
5. 模型建立与求解（主体，按子问题分节，每节约 3-6 页）
6. 模型检验与灵敏度分析（2-4 页）
7. 模型评价与推广（1-2 页）
8. 参考文献
9. 附录（程序代码、详细数据表）

### 摘要写作模式

一等奖摘要通常包含以下要素（不强制顺序）：
- **问题背景**（1 句）：简述研究背景和意义
- **研究方法**（2-3 句）：针对每个子问题列出所用模型
- **关键结果**（2-3 句）：具体数值结果，必须是实际数据，不是定性描述
- **创新点**（1 句）：方法的改进或创新之处
- **关键词**：4-6 个，按模型→方法→领域的顺序排列

摘要篇幅参考：CUMCM 约 800-1200 字（中文），MCM/ICM 约 250-400 词（英文）。

### 图表规范

**编号格式**：
- 图：全文连续编号（图1、图2……），不按章节编号
- 表：全文连续编号（表1、表2……）

**题注位置**：
- 图题注在图下方：`图N 标题`
- 表题注在表上方：`表N 标题`

**引用格式**：
- 正文中每个图表必须至少被引用一次
- 引用写法：如图1所示／见表2／（图3）
- 图表出现位置应在首次引用的同一页或下一页

**图表质量**：
- 分辨率不低于 300 DPI
- 坐标轴字体不小于 8pt
- 坐标轴有标签和单位
- 配色在黑白打印下仍可区分
- 默认不使用网格线（获奖论文普遍特征）

### 公式排版

- 重要公式居中，编号右对齐：`(1)`、`(2)`……全文连续编号
- 公式属于句子一部分时行内排版
- 变量符号斜体，函数名（sin、ln、max）正体
- 向量和矩阵使用粗体
- 公式中的符号必须与符号说明表完全一致

### 三线表规范

获奖论文普遍使用三线表：
- 顶线（粗线）+ 栏目线（细线，表头下方）+ 底线（粗线）
- 无竖线、无中间行线
- 表内数字小数点对齐
- 单位标注在表头括号内或单独列

### 字体与段落

CUMCM 无全国统一的字体/行距强制规定，但一等奖论文普遍采用以下标准：

| 元素 | 字体 | 字号 | 对齐 |
|------|------|------|------|
| 论文标题 | 黑体 | 三号 (16pt) | 居中 |
| 一级标题 | 黑体 | 四号 (14pt) | 居中 |
| 二级标题 | 黑体 | 小四 (12pt) | 左对齐 |
| 正文 | 宋体 | 小四 (12pt) | 两端对齐 |
| 表格内容 | 宋体 | 五号 (10.5pt) | 居中/左对齐 |
| 页脚页码 | - | 小五 (9pt) | 居中 |

- 行距：单倍行距
- 页眉：不使用（CUMCM 论文不设页眉）
- 页边距：四边 2.5cm（左侧装订）

### 附录与代码规范

附录包含全部可运行源代码。一等奖论文的附录代码特征：

- 代码使用中文注释说明关键步骤
- 随机种子显式设置确保可复现
- 文件路径使用相对路径，不写绝对路径
- 输入输出清晰标注
- 代码结构按子问题组织，与正文模型编号对应

### 参考文献格式

一等奖论文普遍使用顺序编号制（GB/T 7714 风格）：

- 正文引用：`[1]`、`[1-3]`、`[1][3]`
- 按首次出现顺序编号
- 引用书籍需标注页码：`[1] p.45`
- 常见文献类型标识：[M]专著、[J]期刊、[EB/OL]网络资源
- 一等奖论文通常引用 8-20 篇参考文献
- **2025 年起新增**：使用 AI 工具必须列入参考文献，格式：
  `[N] 工具名称, 版本, 开发者, 使用日期.`

### CUMCM 篇幅的硬约束与质量目标

- 2026 年官方《全国大学生数学建模竞赛论文格式规范》规定摘要原则上不超过一页、正文不超过 30 页，没有规定最低 15000 字或最低 20 页。
- 为防止论文过短，工具默认用约 15000 字词单位和约 20 页作为 CUMCM 完整度质量目标；它们不是官方最低要求，可由当届规则或用户要求覆盖。
- 页数必须以 DOCX 渲染成 PDF 后的实际页数为准，不能根据字符数猜测。

## 模板驱动生成

推荐流程是“官方参考模板 + `python-docx` 内容构建 + OMML 公式 + 结构校验 + 渲染抽检”。

```python
from pathlib import Path
import sys

skill_root = Path("<SKILL_ROOT>")
sys.path.insert(0, str(skill_root / "tools" / "docx" / "scripts"))
import paper_format as pf

doc = pf.new_document(
    contest="cumcm",
    template_path=Path("<PROJECT_ROOT>") / "当届官方模板.docx",
    preserve_template_content=False,
)
pf.title(doc, "论文题目")
pf.abstract_title(doc)
pf.body(doc, "摘要正文。")
pf.keywords(doc, "关键词一；关键词二")
pf.save_document(doc, Path("<PROJECT_ROOT>"), contest="cumcm")
```

传入模板时，`paper_format.py` 保留模板的样式、分节和页面设置。官方模板含固定摘要页、编号页或占位符时使用 `preserve_template_content=True` 并在原位填充；只借用样式时使用默认值清除示例正文。未提供官方模板时，`cumcm` 和 `mcm-icm` 配置仅提供构建基线，必须再与当届官方规则核对。

## 公式

- 使用 `paper_format.equation()` 或 `equations.py` 写入 Word 原生 OMML。
- 支持常用希腊字母、关系符号、反三角函数、分式、根式、上下标、矩阵与分段表达式，包括 `\nu`、`\mu`、`\approx`、`\arcsin`、`\arccos` 和 `\arctan`；未知命令、未闭合分组和不支持环境会明确失败。
- 复杂公式优先使用 Pandoc 的成熟 LaTeX→OMML 转换，再进行 DOCX 校验。
- 最终公式必须可编辑，不能是截图或纯文本 LaTeX。

## 完整 LaTeX 论文转换

```powershell
python ../../../../tools/docx/scripts/equations.py convert-latex "<PROJECT_ROOT>/完整论文-LaTeX/main.tex" --output "<PROJECT_ROOT>/完整论文.docx" --template "<PROJECT_ROOT>/当届官方模板.docx"
```

该命令需要系统已安装 Pandoc，使用 citeproc 处理 BibTeX 引用，将公式转换为原生 OMML，递归展开项目内的 `\input`/`\include`，并从 LaTeX 项目目录读取相对图片。任何 Pandoc 警告默认阻断 DOCX 发布；只有逐项检查后才能同时使用 `--allow-warning` 和 `--override-reason`。成功转换会生成 `.conversion.json`，用于核对输入、输出、模板哈希、Pandoc 版本和复现命令；交付前运行 `equations.py verify-conversion "<PROJECT_ROOT>/完整论文.docx"` 重新计算全部哈希。自定义宏、浮动体、交叉引用和参考文献样式仍须人工核对；未提供 CSL 时尤其要检查引文样式。输出仍需执行本规范后续的结构校验和渲染抽检。

## 表格与图

- 表格必须可编辑；三线表使用 `three_line_table()`。
- 图来自Tide真实运行结果，可从候选图中选择。
- 每幅图和每个表必须有连续编号与题注，并在正文中至少引用一次；单位和数值必须一致。

## 校验

```powershell
python ../../../../tools/docx/scripts/check_env.py
python ../../../../tools/docx/scripts/self_check.py
python ../../../../tools/docx/scripts/office/validate.py "<PROJECT_ROOT>/完整论文.docx"
```

生成后调用：

```python
issues = pf.validate_paper_structure(doc, contest="cumcm", rendered_pages=实际页数)
```

该检查会报告篇幅、公式/图/表数量、图表编号与正文引用、参考文献双向对应以及页数问题。默认 15000 字词单位、20 页、公式 5 个、图 8 幅、表 3 个均为 CUMCM 完整度质量目标；其他竞赛同样默认至少 8 幅正式图。2026 年 CUMCM 正文 30 页上限属于已经核验的官方硬约束。使用其他届次或竞赛时必须传入相应阈值；降低默认目标必须记录官方条款或用户要求。OOXML 校验通过后仍需渲染抽检，因为 XML 合法不等于版面正确。
