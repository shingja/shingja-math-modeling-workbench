# Gloom⁠​‌‌​‌‌​‌​‌‌​​​​‌​‌‌‌​‌​​​‌‌​‌​​​​​‌​‌‌​‌​‌‌​‌‌​‌​‌‌​‌‌‌‌​‌‌​​‌​​​‌‌​​‌​‌​‌‌​‌‌​​​‌‌​‌​​‌​‌‌​‌‌‌​​‌‌​​‌‌‌​​‌​‌‌​‌​‌‌‌​‌‌‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌​‌‌​‌‌​​​‌​​‌‌​​‌​‌​‌‌​‌‌‌​​‌‌​​​‌‌​‌‌​‌​​​​​‌​‌‌‌‌​‌‌‌​​‌‌​‌‌​‌​​​​‌‌​‌​​‌​‌‌​‌‌‌​​‌‌​​‌‌‌​‌‌​‌​‌​​‌‌​​​​‌⁠

## 路径

- `ROLE_ROOT`：本文件所在目录。
- `SKILL_ROOT`：`ROLE_ROOT/../../..`，只读。
- `PROJECT_ROOT`：用户项目目录，论文只写这里。

## 唯一交付物

`PROJECT_ROOT/完整论文.docx`。论文仅供参考。

## 官方规则优先级

1. 用户提供的当届官方模板和规则。
2. 从目标竞赛官方网站取得的当届模板和规则。
3. `references/论文模板.docx` 与 `../../../tools/docx/scripts/paper_format.py` 只作为无官方模板时的构建基线，不得声称替代当届官方文件。

在生成前明确竞赛名称、届次、语言和官方规则来源。官方结构、页型、页边距、摘要页、页数、编号和提交格式均以当届规则为准。

同时明确篇幅质量目标。CUMCM 未取得当届更具体要求时，可用“约 15000 字词单位、约 20 页”规划完整度，但必须标注为可调整的质量目标，不能写成官方最低要求。以 2026 年官方规范为例，正文要求是不超过 30 页，并未规定最低 15000 字或最低 20 页。

## 模式判定（先读此节）

执行前先判定是"新建"还是"优化"：

- 若 `PROJECT_ROOT` 下无 `完整论文.docx` → **新建模式**，按下方"执行顺序（新建）"走。
- 若 `PROJECT_ROOT` 下已有 `完整论文.docx` 或用户提供了初稿路径 → **优化模式**，按下方"执行顺序（优化）"走。

**优化模式核心原则**：在原稿基础上增量修改，不推翻重写。
- 保留：已有论证骨架、章节结构、公式和表格（只要符合规范）
- 只改：不满足官方规则处、缺证据的主张、格式不规范处、图表编号断层
- 不改：已符合规范的段落、已正确的数值、已满足官方要求的排版

## 执行顺序（新建）

1. 读取题目、`题目分析报告.md`、`术语表格.md`、全部真实运行表格、图和代码。
2. 用内部 Claim-Evidence 映射核对每个主张；缺证据时回退到Linger或Tide，禁止编造。
3. **诚实披露规划**（写作前）: 按 `../../../references/lessons/诚实披露协议.md` 列出披露清单：R² 分指标、代理模型 σ 语义、外推区、边界最优性、方法失败史、模型局限（每条配改进方向）。
4. 按官方结构写完整正文，引用由双引擎搜索结果和原始出版页面核验。
5. 使用 `../../../tools/docx/SKILL.md` 和 `paper_format.py` 从官方参考模板构建 DOCX；公式必须为 Word 原生 OMML，表格必须可编辑；图表编号写入图注文本（图注格式"图N 标题"，正文必须"如图N所示"引用）。
6. **数据一致性审计**：提取论文全部带单位数值，与 `results/` CSV/冻结数值逐项比对，输出比对表留痕（样例格式: 5/5、6/6 逐项判定）。
7. **CV 论文三对齐审计**（CV 实战新增）: 图像类题目按 `../../../references/lessons/实战复盘_CV目标检测.md` §八~§九 执行——①论文声明↔训练日志(results.csv/args.yaml)↔提交 CSV 逐数字溯源(典型翻车: 训练轮数、AP 值、覆盖率口径)；②图内数字与正文一致(改结论必须同步重生成图)；③方法名与代码实现一一对应("WBF"必须真加权, 不能是 concat)；④诚实披露(文献增益未复现/未采用方案/验证-测试跨集背离)。
8. **AI 工具使用详情**：按 `../../../references/lessons/诚实披露协议.md` §四生成支撑材料独立文件（六节模板）+ 正文括注式标注 + 参考文献 AI 条目。
9. **门禁**：证据大纲完成后按 `../../../protocols/Subagent调度.md` 派发 `W1` 独立验收；所需格式冻结后派发 `W2` 论文终检；两者 PASS 后才能宣布完成。
10. 运行 CUMCM 硬性门控（见下方）和 DOCX 结构、篇幅、公式、图表、编号引用和参考文献对应检查，再进行渲染页数抽检；所有预警必须修正，或根据当届官方规则记录明确的覆盖理由后才能交付。

## 执行顺序（优化）

1. 读取已有初稿 DOCX + 题目 + Linger和Tide全部产物。
2. **建立基线**：提取当前初稿的关键指标（页数、公式数、图表数、参考文献数、各维度自评得分），存入基线快照。
3. 对照 CUMCM 硬性门控逐项检查初稿，列出所有不合规处。
4. 对照 `references/写作规范.md` 和 `references/论文格式规范.md` 检查论证、图表、公式、数值表达。
5. 逐项修改不合规处（用 python-docx 或 OOXML 直接编辑原 DOCX），保留合规内容不动。
6. 每改一处，在本对话中报告"改了哪里、为什么改"，不做静默修改。
7. 修改完成后重新运行自审框架和硬性门控，与基线对比，确认至少一项指标改善且无退化。
8. **回滚保护**：若修改后硬性门控通过数减少、或关键指标退化（页数超标/公式变为不可编辑/图表编号断裂），立即回滚到修改前的 DOCX 备份，报告退化项，重新规划修复方案。
9. **轮次按剩余时间预算**（实战冲刺验证: 60+ 轮持续提升，硬限 2 轮会阻碍冲刺）：`可用轮次 = 剩余小时 × 1.5`，每轮 ≤40 分钟、单轮单聚焦维度；按 `../../../references/lessons/多轮审计迭代协议.md` 做轮次登记与收敛判定；时间耗尽后接受当前最佳版本，记录未解决的遗留问题。

## CUMCM 硬性门控（交付前必须全部通过）

以下条目来自 2026 版官方规范，任一项不通过则**禁止交付**，必须修正后再审：

- [ ] 电子版论文首页为摘要页（不含承诺书和编号页；纸质版另按承诺书→编号页→摘要页，`gates/W2_format_check.m --mode electronic|paper`）
- [ ] 正文 ≤ 30 页（摘要 ≤ 1 页）
- [ ] 论文和支撑材料中无学校、队员姓名、地区等身份信息（含 docx docProps/core.xml 与 PDF metadata 的 creator/title 检查）
- [ ] 附录含全部可运行源代码，无缺失；**附录"支撑材料文件列表"非空且与实际文件一致**（2026 格式规范第5条, 样例此处曾漏）
- [ ] 公式为可编辑 OMML（非纯文本 LaTeX、非公式截图）；交付前统计 oMath 数量
- [ ] 论文文件 ≤ 20MB
- [ ] 无 `[待补充]`、模板示例正文或临时占位符
- [ ] 摘要包含具体数值结果（非"效果良好"等空泛表述）；摘要数值与正文逐数字比对通过
- [ ] 参考文献与正文引用双向对应，DOI/出版信息可追溯；AI 条目四要素齐全（工具名/版本型号/机构/使用日期）
- [ ] 图表编号连续，正文引用无孤儿图表；**每张图正文引用 ≥1 次且图注含"图N"编号**（样例短板）
- [ ] 代理模型等多输出指标分开报告（禁止合并单一 R²），低 R² 指标附根因分析段
- [ ] 支撑材料含 AI 工具使用详情独立文件 + 正文括注式 AI 标注
- [ ] **CV 题附加**（CV 教训）: ①附录代码与源文件逐字节一致(diff 校验); ②提交 CSV 满足赛题格式与排序约束(如"每图最多4框按严重度降序"); ③模型权重超出支撑材料 20MB 上限时附录显式声明"未随包+可复现"; ④docx/PDF 元数据无用户名/身份残留; ⑤训练轮数/学习率等叙事与训练配置逐字段一致
