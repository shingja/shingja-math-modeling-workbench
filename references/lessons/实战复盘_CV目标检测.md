## 一、题目画像(与国赛传统题的差异)

| 维度 | 传统数模题 | 本题(CV 检测类) |
|---|---|---|
| 输入 | 少量结构化数据/物理参数 | 数千张固定尺寸 RGB 图像 + YOLO 格式标注 |
| 任务 | 建立机理/优化模型求解析或数值解 | 训练神经网络, 黑箱测试集上出提交文件 |
| 评价 | 论文+结果, 指标可自证 | **黑箱评估**: 测试集标签赛末公布, 提交结果 CSV |
| 模型 | 公式推导是核心 | 基线(预训练 YOLO)+训练策略+后处理是核心 |
| 分数来源 | 建模深度 | 检出/定位/分类准确率 + 消融实验说服力 |
| 可复现 | 算法确定性 | 训练随机性, 需 seed/权重/日志三重冻结 |

三问题递进链: ① 二分类(有无损伤) → ② 检测定位+三分类 → ③ 多维优化。逐题“上游给下游当输入”的链式结构与传统题相同, 但每题的“模型”都是神经网络。

## 二、数据拓扑审计(CV 版, 范本流程)

1. **拆分核对**: 官方数据自带划分。自行拆 train/val 必须显式声明(论文写“从官方训练集划出验证集”), 别让评委以为数据规模造假。
2. **标签统计**(Linger必做, 直接决定方法): 实例数按类统计(发现严重类别不平衡, 稀有类占比约一成); 验证集做面积分箱(发现大量 <1% 面积微小目标)与宽高比统计(发现长条状类几何先验)。→ 结论: 小目标+类别不平衡+几何先验三难题, 不是套个 YOLO 就完。
3. **关键事实: 训练/验证 100% 含损, 零负样本** → 问题一二分类不能直接训分类器。这是数据拓扑审计在 CV 题的等价物: 不看就翻车。

## 三、问题一范式: 无负样本二分类

**检测推导法**(最终方案): 检测框非空 → 有损。逻辑: 目标检测是分类的超集。实测验证集覆盖率 >99%。
**外部负样本法**(备选, 论文中诚实披露未采用): 外部公开数据集补无损图训轻量 CNN, 存在域偏移风险。
**写作要点**: 两条路径都写, 明确“哪条用了、哪条为何不用(数值理由)”——这就是诚实披露协议的 CV 版实践。

## 四、问题二范式: YOLO 基线 → 训练策略 → 架构增强

### 4.1 训练充分性优先(最大单一增益, 相对提升约 52%)
- YOLOv8n 短训基线 → 分阶段学习率衰减延训数倍 epoch → mAP50 相对提升约 52%。
- 核心洞察: **“充分训练小模型 > 浅度训练大模型”**(4GB 显存硬件约束下)。
- 诊断方法: 看 epoch 曲线——短训结束时三项 loss 仍在下降、mAP 无平台 → 未收敛 → 延训。

### 4.2 分阶段学习率衰减延训(参数实录)
- 初训: AdamW + cos_lr + warmup; 延训: lr0 降半(首轮 50%), patience 加大, resume 续训到数倍 epoch。
- 事实对齐教训: 论文写训练史必须逐项对 args.yaml/results.csv(本次审计发现论文的“初训 lr → 延训 lr”叙述与实际“整 run 单一 lr0、中途 resume”不符, 已修)。

### 4.3 架构增强: FSF 频域-空间融合 + FIM 边缘监督
- 思想: 空间域卷积分辨率下采样丢高频细节 → 把频域先验显式注入颈部。RFFT2 → 可学习逐通道频率掩码(sigmoid) → IRFFT2 → 压缩门控残差融合。每尺度仅数百掩码参数, 即插即用不改变 shape。
- FIM: Sobel 物理先验边缘监督。非均匀加权 L_phy(强边缘加权 / 弱边缘降权)。**诚实披露**: 本实现 L_phy 未接入训练 loss(论文局限性明确写)——“文献方法我们没复现到”是加分写法, 不是扣分。
- 注意: 文献(PPFS-YOLO, Sensors 2026, 26(10), 3224)无官方代码 → 按论文独立重写, 参数/性能与原文差异全部显式披露(参数量差异、性能差距不遮掩)。

### 4.4 互补模型
- 更大 backbone 短训(架构多样性来源); 稀有类专项微调(从频域边缘模型微调, 小幅提升后再加权进集成)。

## 五、问题三范式: 集成与后处理

1. **WBF 加权框融合**: 多模型预测按 IoU≥0.55 聚类, 簇内按 conf×weight 加权平均坐标与置信度; 权重按验证 mAP50 比例分配。代码必须真实现加权平均(本次审计抓出“权重加载了但没用”的 P0 问题)。
2. **多尺度 TTA**: 双分辨率 + 水平翻转, 覆盖率 +~1pp, 稀有类提升最明显。
3. **逐类置信度阈值**: 按类别中位置信度差异化(系统性偏低的类降阈值补召回)。
4. **Severity 排序 + Top-K**: conf^γ×area(γ 网格搜索), 每图最多 K 框按严重度**降序**输出(赛题硬性要求, 且每类至少保 1)。
5. **消融实验链**: 基线→优化器→延训→更大 backbone→FSF→WBF→稀有类微调→TTA→阈值+Severity, 每步记边际增益。消融是 CV 题论文的“建模深度”等价物。

## 六、成绩与教训（只记相对结论）

| 项 | 结论 |
|---|---|
| 延训 | 最大单一增益(相对 +52%) |
| 更大 backbone / 稀有类微调 | 分别贡献架构多样性与稀有类召回 |
| 四模型 WBF+TTA 提交 | 覆盖率高(>99%), 三类框数按类严重度分布合理 |
| 测试集真值核验 | **验证集指标明显高于测试召回(跨集背离)**——诚实地写进局限性, 不遮掩 |

## 七、CV 提交包工程(Tide必读)

1. **路径封装模式**: 代码一律 `ROOT = Path(__file__).resolve().parent` 起步, 数据/权重/输出全部相对定位——本次迁移目录后多个脚本因硬编码旧盘符路径失效, 是 P1 级教训。
2. **权重与体积上限**: 模型权重合计超支撑材料上限 → 附录声明“权重未随包, 训练脚本可复现”是合规解。
3. **附录代码 = 源文件逐字节一致**(diff 校验, 本次修复后全部 OK)——评委复现的第一关。
4. **device 自动检测**: 'cuda:0' if torch.cuda.is_available() else 'cpu'——别让脚本在无 GPU 机器上直接崩。
5. **提交 CSV 格式**: 归一化坐标列 + 无置信度列时“按严重度排序”不可验证——输出前必须排好序。

## 八、CV 论文写作要点(Gloom)

1. **数值三对齐审计**(本次审计核心产出): 论文声明 ↔ 训练日志(results.csv/args.yaml) ↔ 提交 CSV, 每数字可溯源。典型翻车点: ①论文写的微调 epoch 数与实际不符; ②论文引用了提交 CSV 中不存在的数据; ③覆盖率口径三处不一致。
2. **图内数字与正文一致**: 图里画“100%”、正文改“99%”会被抓——改结论必须同步重生成图(保留生成脚本)。
3. **叙事与事实分离**: “WBF 加权融合”写在论文但代码只 concat = P0。每个方法名都要在代码里找到对应实现。
4. **局限性写成方法学洞察**: “L_phy 未集成(文献增益未复现)”、“验证集好但测试召回低的跨集背离”——评委买账的诚实。
5. 摘要句式沿用“逐问五要素”: 针对问题X, 用[方法]解决[难点], 实现[具体数值]。

## 十、下次 CV 题可直接复用的检查链

Linger: 数据拓扑(拆分/类分布/面积/宽高比/负样本) → 选基线(预训练 YOLO) → 写指标目标卡(mAP50 基线值+文献 SOTA)。
Tide: 环境(device 自动) → 基线短训快跑 → 看曲线判断训练充分性 → 延训 → 架构增强(库内 0625 卡) → 集成(0624 卡) → TTA/阈值/Severity → 提交 CSV → run_all --verify-only。
Gloom: 数值三对齐审计 → 图内数字同步 → 方法名与代码一一对应 → 诚实披露(未复现/未采用/跨集背离) → 附录代码 diff → 元数据清理 → 渲染 PDF 页码/页数复核。

## 十一、开发史与环境坑清单

**阶段线**: 阶段A 原机调研(环境探测, torch 版本, 4 Session: 读题→资源搜集(仓库/数据集/论文)→数据准备→文献精读+架构实现) → 阶段B 训练期(4GB 显存 GPU: 文献方法测试 → 短训基线 → 三模型对比 → 一条增强路线失败归档放弃 → 边缘模型 → 稀有类微调 → 延训 → 更大 backbone → 分类器迭代 → 提交) → 阶段C 换机迁移(盘符迁移/目录重组) → 阶段D 终审修复。

**环境坑**(每坑已附修复路径, 全来自本项目的失败分析/迁移文档):

| 坑 | 根因 | 对策 |
|---|---|---|
| AMD GPU 无法训练 | Windows 无 ROCm, DirectML 不被 ultralytics 支持 | 换 N 卡或只用 CPU 推理 |
| 老卡 AMP→NaN | ultralytics 对该卡型有正则黑名单 | amp=False 全 FP32, 接受慢速 |
| AMP+deterministic=True→NaN | 两者冲突 | 只开其一 |
| 无 AMP 时每 epoch 数十分钟 | 算力受限 | 用 nano 模型 + 小 batch, 延训补性能 |
| 残留 python 进程冻结训练 | 内存耗尽进 swap | 训练后 taskkill 清理 + 监控脚本 |
| VRAM 残留 | CUDA context 未释放 | 每次训练后重启进程 |
| Python 3.14 太新 | C 扩展不兼容 | 3.10~3.12 |
| 中文路径崩溃 | GBK 编码 | 数据目录全 ASCII |
| GitHub/PyPI 被墙 | 代理不稳 | curl zip 包 + 国内镜像 |
| 假 PDF(HTML 重定向伪装) | 下载源伪造 | verify_integrity 查 %PDF- 魔数 |
| 权重下载失败 | GitHub assets 被墙 | 旧项目拷贝 |

**流程教训**:
1. **换机知识转移三件套**: RESOURCE_INDEX(资源清单)+ORIGINAL_MACHINE_STATE(环境快照)+MIGRATION_GUIDE(坑+操作)——换了多台机器仍能续战的关键。
2. **失败归档三段式**: `_archive_failed/` + FAILURE_ANALYSIS.md(失败清单表→根因→正确做法)——低分增强路线直接归档, 不再恋战。
3. **文档漂移**: 会话日志只维护到阶段 A, README 停在迁移前——**日志维护必须跟训练同步进行, 否则后段历史全靠考古**。
4. **Phase 编号管理**: 阶段编号 + optimization_history.csv 递进消融链——与 skill 的 M-Loop metric_trajectory 同构。
5. **硬件自适应**: 按 VRAM 自动降模型集(n/s/11n)与 batch——4GB 显存下“充分训练小模型”是本题第一贡献。
