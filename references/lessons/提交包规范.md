## 一、结构模板

```
提交材料/
├── 完整论文.docx          (≤20MB, 电子版首页=摘要页)
├── 参赛信息封面.docx      (需身份标识的赛事单独放, 不混入论文)
├── 支撑材料.zip           (所有支撑文件打成单个压缩包, 2026 格式规范第11条)
└── README.md              (由清单脚本生成, 见 §四)
支撑材料/ 内容:
├── 数据/                  附件原始数据(题目PDF+附件xlsx)
├── 源代码/               全部 py/m + requirements.txt(seed/版本下限)
├── 结果数据/             问题{N}_{内容}.csv (UTF-8无BOM)
├── 图表/                 交付侧"图N 中文名.png"(300DPI)
├── AI 工具使用详情.pdf    规定文件名, 六节结构(见诚实披露协议)
└── SHA256_hashes.json     全量哈希(输入+输出+源文件)
```

## 二、白名单/黑名单

**黑名单(必须清除)**: `__pycache__/`、旧版论文、审计中间脚本、临时 CSV、`.git/`、`~/` 残留目录、backup 文件、个人笔记。
**白名单原则**: 每个进包文件都要能回答"评委看它的目的是什么"。样例从 93 文件砍到 71 文件的清理就是这个原则。

## 三、干净目录重跑验证(硬性, 坑9 的直接对策)

1. 建空目录 `verify/`, 只复制: 源代码/ + 数据/ + requirements.txt
2. 在该目录按复现清单完整跑一遍: `pip install -r requirements.txt → python main.py → ...`
3. 断言: 每个脚本 import 的符号在包内存在; 无对包外脚本的 import; 关键数值与冻结数值一致(容差内)
4. 失败 = 提交包不合格, 修复后重跑
5. 特别注意: 论文引用的每个增强数值(E1-E9/KKT/RSS)必须有生成它的代码在包内

## 四、README 清单脚本化

README 的 文件数/大小/SHA256/依赖/运行步骤 全部由脚本生成, 禁止手写:
```python
# 生成实际文件清单, 与 README/附录声明比对
# 教训: 手写 README 声称的文件/SHA256 实际不存在
```

## 五、身份信息五查

- [ ] PDF metadata: title/author 干净
- [ ] xlsx 作者字段
- [ ] 代码注释/README 无队名队员名

## 六、压缩与哈希

- 支撑材料打成**单个** zip(不是散文件, 2026 规范第 11 条)
- 论文 ≤20MB 不压缩
- SHA256_hashes.json: 输入数据(附件xlsx+csv)+全部输出 CSV+全部源文件; 验证脚本比对
- 锁定后任何文件变动 = 更新哈希 = 重新审计(多轮审计协议 §五)

## 八、CV 题增补(CV 实战, v4.4.0)

- **权重体积决策**: 深度学习权重(.pt)动辄数十 MB(CV 实战: 权重合计超出 20MB 上限)。合规解 = 权重不随包 + 附录声明"可由训练脚本复现"; 若必须携带, 只挑最小且论文声称使用的。见 `实战复盘_CV目标检测.md` §七。
- **附录代码一致性**: 评委复现第一关 = 附录代码与源文件逐字节一致(修复后全部 diff 全同); 提交前跑一次 diff 校验。
- **路径封装**: 提交包代码一律 `ROOT = Path(__file__).resolve().parent` 相对布局, 数据/权重/输出按包内子目录组织(教训: 脚本硬编码旧盘符路径, 迁移后失效)。
- **元数据五查加一**: docProps lastModifiedBy 常残留 OS 用户名（实战: 残留了用户名别名）——core.xml 的 lastModifiedBy 也查。
