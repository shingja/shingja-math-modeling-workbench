## 教训1: 摘要数值与正文必须全量一致

**事例**: 旧版摘要写的鲁棒方案参数与正文不一致; 多轮修改后摘要未同步, 被逐数字比对抓出。
**建议**: 提取摘要全部数字, 逐个 grep 正文验证, 留痕比对表。**硬门控**: 摘要数值逐数字比对(不是"数值一致"一句话)。

## 教训2: R² 按输出指标分开报告

**事例**: GPR R² 按输出指标分开报告（大部分指标 >0.99, 最低的两个仅 0.4-0.6, 分别附物理根因: 代数关系控制 / 信号变异域窄 / 标量参数维度不足）。统一声称">0.99"被终审抓出。
**建议**: 代理模型性能表按输出分行; 低 R² 指标强制附根因分析段, 把"精度差异"写成方法学洞察。

## 教训3: 诚实性披露双保险

**事例**: §6.2.6"发现的普遍意义与诚实性声明"完整记录 GPR 失败(R²=-10.27)→诊断(条件数>10¹²)→修复→验证全流程; §9.2 模型局限 5 条各配改进方向。
**建议**: 固化"诚实性小节"模板: 失败案例/外推区域/模型局限三件套, 每条配改进方向。评审多次把诚实披露列为加分点。

## 教训4: 数据空白区显式标注+物理约束

**事例**: 某变量组合的零样本区域 → "数据拓扑分析"节(域空白"孤岛/大陆"二分结构)→ 物理耦合约束 → 无约束双轨对比 → 排除该区域取值的物理验证。
**建议**: 数据预处理节加"拓扑分析+覆盖率统计+空白区识别+外推约束"四步。

## 教训5: 图注编号必须活在图注文本里

**事例**: 全部图注文本均无"图N"前缀, 正文零处"如图N所示"; 表/公式/章节交叉引用全部完备, 唯独图缺。本次最明确的排版短板。
**建议**: **硬门控**: 每图正文引用次数 ≥1 + 图注含编号; 图表编号连续无孤儿升级为引用覆盖率检查。

## 教训6: 三线表用 Word 表格样式实现, 跨页写续表

**事例**: 样式"三线表1"(顶/底线 1.5pt + 表头下线 0.5pt, 无竖线), 样式级实现非手动画线; 跨页表写"续表N 表题"。
**建议**: 表注置于表上方、图注置于图下方; 续表格式: "续表N 表题"。

## 教训7: 公式全 OMML, 交付前统计数量

**事例**: 数百个 oMath, 表格单元格列头也用 OMML, 零公式截图; PDF 文本可搜索。
**建议**: 交付前统计 oMath 数量 + 表格内嵌公式检查(python-docx 提取公式文本为空, 审计需解析 document.xml)。

## 教训8: AI 声明模板: 量化贡献+写 AI 的失败

**事例**: AI 工具使用详情: 贡献占比列(10%/20%/10%/5%)、示例 3 写"AI 建议 alpha=1e-10 导致 Cholesky 分解失败, 队员发现标准化依赖并修复, 该修复是论文重要方法论发现"。
**建议**: 六节模板: 依据/基本信息表/目的环节表(含占比)/关键交互记录(提示词+回复要点+采纳情况三段式)/采纳修改总结/基本原则+责任声明。写 AI 的失败反衬独立工作是实战验证的有效策略。

## 教训9: 数据一致性审计表留痕

**事例**: 论文数值 vs 支撑材料 CSV 逐项比对: 各口径（相关系数/优化结果/权重扫描/TOPSIS/MC 收敛）全部通过, 比对表作为交付留痕。
**建议**: 提取论文全部带单位数值与 CSV/代码输出比对, 输出比对表。**硬门控**: 论文数值 ∈ 结果数据 CSV 全量。

## 教训10: 代码交付前去 AI 化

**事例**: 移除"Tide v3.0 | T1 Competition Level"角色标签、竞赛标签、"F1 FIXED"版本标记、装饰分隔线。
**建议**: Tide→Gloom交接加"去 AI 化"检查(正则移除角色标签/竞赛名/emoji 分隔线/FIXED 标记); 附录代码带行号全量贴入。

## 教训11: 附录"支撑材料文件列表"是硬条款

**事例**: 2026 格式规范第 5 条要求附录含支撑材料文件列表; 本次附录"A 支撑材料目录"标题下内容为空——提交前未闭合的合规风险点。
**建议**: **硬门控**: 附录文件列表非空且与实际支撑材料文件一致; 附录模板自带文件清单表(文件名/路径/说明)。

## 教训12: 中文排版缺陷程序化扫描

**事例**: 标题多余顿号; 附录残留孤立字母; 小标题被并入 Normal 段落。
**建议**: 扫描脚本: 标题正则(^[0-9.]+、^第.+章、^[一二三四五六七八九十]+、)+残留字符+样式正确性。

## 教训13: 每轮导出带段落索引的纯文本稿

**事例**: paper_text.txt([P序号]段落索引格式)支撑了旧版 vs 最终版差异定位; 也是 AIGC 检测工作底稿。
**建议**: Gloom工作流加"每轮导出版本化纯文本稿"步骤, 用于 AI 率检测、数值 diff、多轮审计。

## 教训14: 定性/示意图标注假设

**事例**: 热阻三分量图内标题"(Order-of-magnitude estimate, see code for assumptions)"。
**建议**: 定性/示意类图强制加"(示意/量级估计)"标注, 防止误导。

## 教训15: README 由清单脚本生成

**事例**: README 声称 71 文件/SHA256/run_all.py/AI 为 Anthropic Claude, 实际最终包无 SHA256 文件、无 run_all.py、AI 是 DeepSeek-V4-Pro——三方脱节。
**建议**: 交付前自动生成实际文件清单并与 README/附录比对; README 从清单脚本生成而非手写。

## 教训16: 文档元数据是身份泄露盲区

**事例**: docx/PDF 元数据 creator="Q"/lastModifiedBy="x shingja"(化名); PDF 标题残留"第一页"。
**建议**: **硬门控"无身份信息"细化**: docProps/core.xml + PDF metadata creator/title 检查 + 全库 grep 队员姓名/学校。

## 教训17: AI 率控制五手段

1. AI 贡献占比量化表(按环节估列)
2. 正文括注式标注 3 处"(…经 AI 工具辅助…, [13])"放在问题分析段/模型假设/公式核对处
3. 诚实性声明小节记录失败 vs 成功案例对比
4. 写 AI 的失败以 AI 局限反衬独立工作
5. 代码去 AI 化
参考目标 <15%; 76 个具体数值引用是强人工特征。

## 教训18: CSV 交付防 BOM + 特殊列说明

**事例**: 13 个 CSV 中 1 个混入 UTF-8-BOM 与其余不一致; RSM 系数表加 NOTE 列注明"系数在标准化空间, 不可物理解释"。
**建议**: CSV 导出规范: UTF-8 无 BOM 统一、矩阵文件 index_col 约定、交付前 BOM 扫描。

## 摘要实战模板(实战验证)

```
第1段: 总起(一句话点题 + 完整方法链 + 参数指标 + 最终交付物)
第2-6段: 固定句式"针对问题N," 逐题收束, 每段只放该题最硬结论+关键数值
  问题1: 分指标 R² 三列 + 方向验证 9/9
  问题2: 核心发现 + 数值跃迁(标准化前后 R² 由负转正)
  问题3: 最优方案参数 + 性能 + KKT 验证
  问题4: 鲁棒方案参数
  问题5: 主导参数及其 |S| 等级
关键词: 6个分号分隔, 与正文方法一一对应
```

## 章节体系实战模板(13章)

标题→摘要→1问题重述→2问题分析(每子问题一段固定句式"本题属于X类")→3模型假设(每条附定量辩护)→4符号说明(表1)→5数据预处理(含拓扑分析)→6模型建立与求解→7物理RSS分析(超纲加分章)→8工程设计规则(定量规则)→9模型评价(优点5+局限5各配改进方向)→参考文献→附录

## 国一论文三增量范式(2016-2023 优秀论文库实测提炼, 2026-08-16)

1. **策略命名制**: 复杂方案给一个名字并在摘要/正文/结论统一使用(实例: 2018B RGV 调度"八步一走", 公开赛题)。名字让评委记住方案, 统一用名防止表述漂移。
2. **精度数据并列展示**: 同一参数多次运行结果并排列表(2017A CT 参数 5 次运行), 证明稳定性优于单次结果; 与 seed 复现体系配合使用。
3. **附录三件套(2018 年起国一标配)**: 文件清单 + 代码全文(带行号) + 运行环境声明。缺文件清单是样例唯一未闭合的合规风险(格式规范第5条), 附录模板必须自带。
