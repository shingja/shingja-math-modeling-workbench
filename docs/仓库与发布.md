## 二、日常操作

### 改完推送（最常用的三条）

```bash
cd "<skills 目录>\math-modeling"
git add -A
git commit -m "feat: 改了什么"
git push
```

### 提交信息前缀约定

与 CHANGELOG 条目对应，沿用本仓库历史习惯：

| 前缀 | 用途 |
|---|---|
| `feat:` | 新能力（范式卡、脚本、门禁、协议） |
| `fix:` | 修复 |
| `docs:` | 文档/教程/README |
| `chore:` | 杂务（版本号、目录整理、测试） |
| `release:` | 定版提交（同时改版本号 + CHANGELOG） |

### 查看状态

```bash
git status -sb                  # 本地 vs 远端
git log --oneline -10           # 最近提交
gh repo view shingja/shingja-math-modeling-workbench
```

### 换电脑 / 新机器接上

```bash

```

克隆下来的目录必须**改名成 `math-modeling`** 放进 skills 目录才会被加载（skill 名 = 目录名）。

> 旧电脑那份副本已经和本仓库**没有共同历史**，别再单独改；要接着开发就统一用本仓库。

## 三、版本号方案

- **内部开发期**：`0.y.z`（当前 `0.1.0`）。语义化版本规定 0.y.z 表示“尚未发布、随时可变”。
- **首次公开发布**：定版 **`1.0.0`**，打 tag `v1.0.0`。
- 之后按 SemVer：`MAJOR` 不兼容变更 / `MINOR` 兼容新增 / `PATCH` 修复。
- CHANGELOG 里 `[1.0.0]`–`[4.4.0]` 是内部序号时代的记录，保留存档，不代表对外发布历史。

### 版本号同步清单（改一处必须改全部）

`test_skill_integrity.py::test_version_consistency` 会自动校验前六处，漏一处测试就红：


### 发版步骤（以首次公开 `1.0.0` 为例）

```bash
# 1. 改上表全部版本号 0.1.0 → 1.0.0
# 2. CHANGELOG.md 顶部加 "## [1.0.0] - 日期" 条目
# 3. 跑测试
python -m unittest discover -s tests -v
# 4. 提交
git add -A && git commit -m "release: 1.0.0"
# 5. 打 tag 并推送
git tag -a v1.0.0 -m "首个公开发布版 1.0.0"
git push origin main --tags
# 6. （可选）建 GitHub Release
gh release create v1.0.0 --title "v1.0.0" --notes-file <(sed -n '/## \[1.0.0\]/,/## \[0.1.0\]/p' CHANGELOG.md)
```

## 五、信息防护规则（每次提交前）

**绝对禁止出现在仓库里的内容**（2026-10-08 已全库清理过一轮）：

| 类别 | 处理方式 |
|---|---|
| 队员/老师真实姓名、指导教师 | 删，或写 `<队员>`、`<指导教师>` 占位 |
| 队伍名、队号、报名号 | 写 `<参赛队名>`，或删 |
| 学校/学院（仓库名除外，见下） | 删 |
| 邮箱、QQ、手机号 | 删 |
| 个人机器路径 `C:\Users\<用户名>\...` | 写 `<skills 目录>`、`<用户目录>` 占位 |
| 本地资料盘路径（桌面目录名、旧项目盘名） | 写 `<资料根目录>`、`<本地项目>` 占位 |
| 竞赛内部编号（选拔包编号等） | 写 `选拔赛` 占位 |

**命名说明**：公开仓库名为 `shingja-math-modeling-workbench`，不含学校简称；作者署名保留在 README、NOTICE 与文件归属行中。

**提交前扫描（有输出就逐条处理）**：

```bash
# 1) 机器个人路径
grep -rInE "C:\\\\Users\\\\[^\\\\]+|D:\\\\桌面|D:\\\\MATH" --exclude-dir=.git .
# 2) 邮箱 / 手机 / QQ
grep -rInE "[A-Za-z0-9._%+-]+@(126|163|qq|gmail|foxmail)\.com|1[3-9][0-9]{9}" --exclude-dir=.git .
# 3) 身份词（人工判断上下文）
grep -rInE "队名|参赛队|指导教师|真实姓名|学号" --exclude-dir=.git . | grep -v "<参赛队名>\|<队员>"
```

**历史提交也要干净**：清理只改了工作区，**旧提交里仍留着清理前的内容**。仓库公开前必须重写历史（重置提交或压成单提交），否则 `git log -p` 就能翻出旧内容。
