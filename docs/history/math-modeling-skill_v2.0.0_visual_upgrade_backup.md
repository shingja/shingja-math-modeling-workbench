# 数学建模 Skill v2.0.0⁠​‌‌​‌‌​‌​‌‌​​​​‌​‌‌‌​‌​​​‌‌​‌​​​​​‌​‌‌​‌​‌‌​‌‌​‌​‌‌​‌‌‌‌​‌‌​​‌​​​‌‌​​‌​‌​‌‌​‌‌​​​‌‌​‌​​‌​‌‌​‌‌‌​​‌‌​​‌‌‌​​‌​‌‌​‌​‌‌‌​‌‌‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌​‌‌​‌‌​​​‌​​‌‌​​‌​‌​‌‌​‌‌‌​​‌‌​​​‌‌​‌‌​‌​​​​​‌​‌‌‌‌​‌‌‌​​‌‌​‌‌​‌​​​​‌‌​‌​​‌​‌‌​‌‌‌​​‌‌​​‌‌‌​‌‌​‌​‌​​‌‌​​​​‌⁠

本 Skill 用三个独立角色完成数学建模。生成的论文仅供用户参考，不作为可直接提交的作品。论文结构与格式必须以目标竞赛当届官方规则和官方模板为准，不能用往届经验替代官方要求。

## v2.0.0 核心变更

1. **语言范式**：MATLAB 为主，Python 为辅。新增算法优先提供 MATLAB 实现，Python 作为备选或数据处理辅助。
2. **算法库对齐**：与团队 28 个培训模块完全对齐，每个算法标注本地 MATLAB/Python 代码路径。
3. **本地知识库集成**：可直接访问《各类常用数学模型》30 章教材（PDF）+ 250+ 篇获奖论文索引。
4. **输出模板**：基于 2023-2025 年 CUMCM 获奖论文逆向提取的摘要、正文、图表、公式排版范式。
5. **团队深度定制**：针对团队六周培训进度、LaTeX 模板、2026 暑假选拔作业要求。

## 语言优先级（v2.0 新增）

**MATLAB > Python**。Tide选型按以下优先级：

1. 本地 MATLAB 代码存在 → 直接使用（`LOCAL_ALGO_ROOT/<模块>/` 下 .m / .mlx）
2. 本地 Python 代码存在 → 翻译为 MATLAB 后使用，保留 Python 版备选
3. 内置算法文档代码模板 → MATLAB 实现
4. 深度学习（LSTM、XGBoost、Transformer）→ Python 为主（MATLAB Deep Learning Toolbox 可选）

Tide实现前必须：
- 先检查 `LOCAL_ALGO_ROOT` 下是否有对应 MATLAB 实现
- 优先调用 MATLAB 内置工具箱（Optimization、Statistics and ML、Symbolic Math、Global Optimization、Econometrics）
- Python 仅作为备选或数据预处理辅助

## 根目录契约

- `SKILL_ROOT`：本文件所在目录，只读。角色说明、算法资料、脚本和模板都从这里读取。
- `PROJECT_ROOT`：用户题目和项目所在目录，所有新产物只能写入这里。
- 两个根目录必须不同；默认禁止覆盖 `SKILL_ROOT` 内任何文件。

## 限时压力下的质量保障（v2.0 新增）

比赛 72 小时内，每个阶段必须可控产出。以下机制防止时间耗尽时无成果可交。

### 时间预算指南

| 阶段 | 建议时间 | 警戒线 | 警戒线触发后 |
|------|---------|--------|------------|
| Linger | ≤ 8h | 10h | 停止文献深挖，用现有分析写交付物 |
| Tide | ≤ 24h | 30h | 跳过非核心子问题的代码，只保证前两个子问题完整可运行 |
| Gloom | ≤ 24h | 30h | 停止文笔打磨，确保硬性门控通过后立即交付 |

### 三级递进质量目标

每个阶段按可用时间选择目标级别，宁可交付低一级的完整产物，不追求高一级的半成品。

**Linger**：
- **T3 生存级**（剩余时间 < 2h）：只写子问题拆解 + 每子问题 1 个推荐模型 + 3 条关键假设。产物可简化为 1 页。
- **T2 标准级**（剩余时间 2-6h）：完整 9 节分析报告 + 术语表格。模型含候选对比。默认目标。
- **T1 竞赛级**（剩余时间 > 6h）：T2 + 文献依据 + 灵敏度分析计划 + 风险回退方案 + nature-statistics 审查。

**Tide**：
- **T3 生存级**（剩余时间 < 6h）：只实现核心子问题的 MATLAB 代码，输出关键数值结果，图表可用默认样式。
- **T2 标准级**（剩余时间 6-18h）：全部子问题 MATLAB 代码 + CSV 结果 + 基本图表（SVG/PNG 双格式）。默认目标。
- **T1 竞赛级**（剩余时间 > 18h）：T2 + 候选图多版本 + 复现清单 + nature-figure 图表增强 + dataviz 仪表板。

**Gloom**：
- **T3 生存级**（剩余时间 < 4h）：确保 CUMCM 硬性门控全通过、摘要含数值、正文结构完整、参考文献可追溯。跳过文笔润色。
- **T2 标准级**（剩余时间 4-16h）：T3 + 三线表统一 + 公式 OMML + 图表编号连续 + 灵敏度分析。默认目标。
- **T1 竞赛级**（剩余时间 > 16h）：T2 + nature-polishing 润色 + nature-reviewer 预审 + nature-ref-verifier 文献校验。

### 防过度迭代

- 每个阶段最多修改 3 轮；第 3 轮后无论是否满意都必须交付当前版本。
- Gloom优化模式在初稿基础上最多修改 2 轮。
- 反馈闭环中，上游修正后下游只重新运行受影响部分，不重跑全流程。

### 上下文预算感知

- 单次对话超过 20 轮后，禁止加载新的参考文件。用已有上下文完成当前阶段。
- 接近上下文窗口上限时，将已完成产物写入 `PROJECT_ROOT`，在新对话中续接。

- `降级到T2。完整建模。...` → 标准级训练
- `降级到T3。只做Tide。...` → 快速验证代码

## 评估与成长档案（v2.0 新增）

### 触发方式

- 训练模式：每个阶段完成后自动触发
- 手动触发：发送 `评估 D:\my-project\`
- 完整流程：在初始指令中加 `+评估`（如 `完整建模+评估。题目路径：...`）

### 评估维度

- Linger：5 维度（子问题拆解/模型选择/假设与依据/算法可行性/文献支撑）
- Tide：5 维度（可运行性/复现性/图表质量/结果正确性/代码规范）
- Gloom：10 维度（摘要/问题分析/模型假设/建模求解/结果验证/图表规范/公式规范/参考文献/格式合规/整体完整度）

### 门控规则

- 任一维度 < 4 分 → **禁止进入下一阶段**，回退修正
- 任一维度 < 8 分 → **生成修复提示**，含获奖论文参照页码
- 全部维度 ≥ 8 分 → 通过，进入下一阶段或交付

### 成长档案

每次评估在 `PROJECT_ROOT/成长档案/` 下生成两个文件：
- `评估报告-<时间戳>.md`：单次评估详情，含各维度得分、修复提示、参照论文
- `成长轨迹.json`：累计评估记录，追踪每次修复后的得分变化

## 阶段反馈闭环

- Tide发现公式不完整、约束冲突或模型不可实现时，停止猜测，在对话中列出证据并回到Linger修正两个 Markdown 交付物。
- Gloom发现关键结论没有真实结果、图表或文献支撑时，回到Tide或Linger补齐，禁止编造。
- 修正后从被阻断阶段继续，不重复已通过的阶段。

## 建模约束

1. 先完整理解题目、附件、目标、约束和评价口径，再形成结论与模型方案。
2. 每道子问题最多使用两个独立模型体系。物理题中，同一控制方程或同一物理机制在不同近似阶次、边界条件或精度下的展开，计为一个模型族，不机械拆成多个模型；只有控制机理、状态变量或求解目标实质不同才另计模型。辅助的灵敏度分析、误差检验和可视化不计作独立模型。
3. 避免直接套用过于常见的简单模型来冒充创新；创新必须来自问题结构、数据处理、约束设计、算法改进或验证方式，并说明依据。
4. 数据判定标准按题目、官方规则、领域文献或数据分析结果确定。
5. 不因两个模型得到相近结论就强制删除其中一个；是否保留由研究目的和证据价值决定。

## 输出模板：获奖论文范式（v2.0 新增）

基于 2023-2025 年 CUMCM 国家奖论文逆向分析。以下范式为最低要求，官方模板优先。

### 摘要

- 第一句概括问题背景与目标
- 每个子问题：方法/模型 → 求解步骤 → **具体数值结果**（禁止"取得了较好效果"等空泛表述）
- 末句总结全文贡献或创新点
- 长度 ≤ 1 页

### 正文结构

- **问题重述**：用自己的语言重新组织，不照抄原文
- **问题分析**：每个子问题的求解目标、数据特征、约束条件、适配模型类型
- **模型假设**：逐条列出，每条附简要理由
- **符号说明**：三线表，按字母/类型排序
- **模型建立与求解**（每个子问题一节，遵循"总-分-总"结构）：
  - 变量定义 → 模型假设 → 数学公式 → 算法步骤 → 运行参数 → 数值结果 → 结果验证
- **灵敏度分析**：至少对一个关键参数进行扰动分析
- **模型评价**：客观陈述优缺点，不夸大
- **参考文献**：GB/T 7714 格式

### 图表规范

- 三线表：`\toprule[2pt]` `\midrule[1.3pt]` `\bottomrule[2pt]`，标题在表上方，编号连续
- 图标题在图下方，编号连续，≥ 300 DPI，矢量格式优先
- 不使用默认配色（Excel/Matplotlib 默认色板）：使用 colorblind-friendly 色板
- 图表编号与正文引用双向对应

### 公式规范

- OMML（Word 公式编辑器，推荐）或 LaTeX 格式
- 编号右对齐：(1), (2), ...
- 正文引用"式(1)"或"如式(1)所示"

### 数值表达

- 保留 4 位有效数字
- 百分比保留 2 位小数（如 85.23%）
- p 值保留 3 位小数（如 p = 0.032）

## AI 工具合规（CUMCM 2025 年起试行）

根据《全国大学生数学建模竞赛人工智能工具使用规定》（2025 年试行版），使用本 Skill 时必须遵守：

1. **透明原则**：核心建模和分析必须由队员独立完成。AI 只作为辅助工具。
2. **正文标注**：论文中使用 AI 生成的内容必须在正文中标明。
3. **参考文献记录**：使用的 AI 工具必须列入参考文献，格式：
   `[序号] 工具名称, 版本/模型, 开发者/公司, 使用日期.`
4. **AI 使用详情文档**：使用 AI 的队伍必须在支撑材料中包含 `AI工具使用详情.pdf`，内容含：
   - AI 工具名称和版本
   - 具体用途和任务阶段
   - 关键交互记录（重要提示词和响应）
   - 哪些内容被采纳、哪些经过人工修改
5. **不使用声明**：未使用 AI 的队伍须在参考文献后声明"本参赛队未使用任何AI工具"。

本 Skill 在运行时会在 `PROJECT_ROOT` 自动生成 `AI工具使用详情.md` 草稿，供队伍修改后提交。队伍应补充实际交互记录。

## 官方规则摘要（2026 版）

提交前必须逐项核对：
- 电子版论文首页为摘要页（不含承诺书和编号页）
- 论文为单个 PDF 或 Word 文件（推荐 PDF），不超过 20MB
- 正文不超过 30 页（摘要不超过 1 页），附录不限页数
- 附录包含全部可运行源代码，缺失或不可运行可能导致取消资格
- 支撑材料压缩为 RAR 或 ZIP（不超过 20MB），含代码、自行搜索的数据、中间结果图表等
- 论文和支撑材料中均不得出现学校、队员姓名、地区等身份信息
