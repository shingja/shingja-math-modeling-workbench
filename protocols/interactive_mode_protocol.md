## 一、触发条件

以下场景自动切换为交互模式 (编号选项, 等待用户输入数字):

| 场景 | 触发时机 | 选项数 |
|------|------|:---:|
| 算法选型 | Linger: 同一子问题有≥2个合理算法 | 2-4 |
| 参数选择 | Linger/Tide: k值/入口策略等 | 2-3 |
| 模型修正 | 联合校准: 模型不可行, 需要回退 | 2-3 |
| 路线选择 | Gloom: 与论文比对后存在多路线 | 2-4 |
| 阻塞处理 | 任意阶段: L1不可用/算法不收敛 | 2-3 |

## 二、交互格式

```
═══════════════════════════════════════════
  [决策点] Q4 入口策略选择
═══════════════════════════════════════════
  基于 T01 5篇论文的比对分析, 存在3种合理方案:

  [1] A016路线 (frac=0.98, r=4.41m)
      → v_max=1.449m/s, 与A016论文偏差3%
      → 推荐: 均衡方案, 安全+性能最优

  [2] 边界路线 (frac=1.0, r=4.5m)
      → v_max=1.522m/s, 与论文偏差8-22%
      → 更保守, 但偏差较大

  [3] A053路线 (frac=0.85, r=3.83m)
      → S曲线更短(12.51m), 更激进
      → 论文A053采用

  请输入数字选择 [1/2/3], 或输入 0 自定义:
═══════════════════════════════════════════
```

## 三、与自动模式的切换

- **默认**: 自动模式 (skill 自主决策, 基于模式匹配和论文共识)
- **触发**: 当 skill 判断存在 ≥2 个合理且后果不同的方案时, 自动切换交互
- **回退**: 用户选择后, skill 记录决策到 decision_log, 恢复自动模式
- **强制自动**: 用户可在 prompt 中加 `--auto` 跳过交互

## 四、交互决策的记录

每次交互决策自动写入 `decision_log.json`:
```json
{
  "id": "D007",
  "type": "interactive",
  "question": "Q4入口策略",
  "user_choice": "1",
  "choice_detail": "A016路线 frac=0.98",
  "reason": "用户选择",
  "timestamp": "..."
}
```

## 五、非交互模式 (快速模式)

如果用户不想被打断, 在 prompt 中加 `快速模式` 或 `--fast`:

```
只做Linger。快速模式。题目: T01...
```

此时 skill 自动选择**论文共识方案** (有共识时) 或**最保守方案** (无共识时), 不询问用户。
