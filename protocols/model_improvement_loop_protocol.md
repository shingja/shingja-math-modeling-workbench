## §1 触发条件

Tide P1(最小可运行结果)通过后, 立即对每个子问题跑 `tools/model_quality_score.py`, 对照Linger"指标目标卡":

- **全部达标** → 继续正式出图/参数扫描, M-Loop 结束
- **任一硬指标不达标** → 触发 M-Loop, 携带证据包回Linger
- **仅软指标不达标** → Tide先尝试数值卫生修复(避坑手册 15 项); 修复后仍不达标 → 升级为 M-Loop

## §2 指标目标卡(Linger新产物)

`PROJECT_ROOT/指标目标卡.md`, 每个子问题一张表:

| 子问题 | 指标 | 目标值 | 硬/软 | 验证口径 |
|---|---|---|---|---|
| 问题2 | 代理模型 R²_test(按输出分指标) | ≥0.90 / ≥0.80 | 硬 / 软 | 10-split 均值, 不允许训练集 R² |
| 问题2 | 交叉验证 R² 标准差 | <0.05 | 软 | 10-split 的 std |
| 问题3 | 最优解优于基准幅度 | ≥5% | 硬 | 与数据集中位数方案比 |
| 问题5 | 灵敏度主导参数三方法一致 | 2/3 方法一致 | 软 | Sobol/Morris/FAST |

设定原则:
- 阈值要**事前可辩护**(来自题目要求/文献/基准方案), 不能事后改口径
- 硬指标 = 不达标论文结论无意义; 软指标 = 影响评分
- 验证口径必须写死(CV 方案/样本量/对比基准), 防止"换口径达标"自欺(坑2 的 CV 泄露同源)

## §3 迭代轮次

### 3.1 每轮动作

1. **Tide** → `[模型迭代] 第N轮: <子问题> <指标> 不达标(实际值 vs 目标值)` + 证据包: 数值卫生自检结果(坑1-15 排查过哪些)、根因诊断假设(实现缺陷 vs 模型局限, 标注"诊断深度")
2. **Linger** 修订, 三选一或组合:
   - 换模型族(同子问题的候选模型)——每子问题≤2 模型族限制**不限制轮次内的候选尝试**, 但论文只保留最终采用模型族
   - 加预处理/特征工程/数据变换(如标准化、对数变换)
   - 换验证口径(仅限口径确有问题时, 如泄露; 禁止为达标改口径)
3. **重新握手** → Tide实现 → P1 复验 → 重跑 scorecard
4. 每轮写入 decision_log(含诊断深度) + `metric_trajectory.json`

### 3.1b 库内耗尽 → 全网扩展层(v4.3.0)

库内迭代 ≥2 轮无改善, 或Linger判定库内无匹配模型族时, 按 `protocols/external_search_protocol.md` 执行全网方法搜索(学术→开源→平台(含赛题级)→数学四层, **只检不禁**: 检查搜索覆盖/效果/结果更优, 风险仅提示不阻止——见该协议 §2)。找到的新方法经候选卡评审后引入, 继续 M-Loop 迭代。引入上限 2 个, 搜索每层 ≤45 分钟。

### 3.2 预算与收敛

- 轮次预算: `可用轮次 = 剩余小时 × 1`(每轮 ≤1.5h), 上限 5 轮(含全网扩展层, 共用预算)
- 收敛判定: ①全硬指标达标 ②连续 2 轮所有指标改善 <2% ③预算耗尽
- ①→正常继续; ②③→进入 §3.4 方案对比终局

### 3.4 方案对比终局(v4.3.0, 全部尝试后的兜底)

预算耗尽仍未达最高标准时:
1. 汇总**所有**已尝试方案(含库内与外部、含失败方案)→ `PROJECT_ROOT/方案对比表.md`(方案/来源含文献/各指标/复杂度/风险/结论)
2. 取指标最优且综合风险可接受者为最终方案
3. 其余方案转为论文**辅助证明与对比分析节**("我们也尝试了 X 与 Y, 因[具体指标差距]未采用"——写法模板见 诚实披露协议 §六)
4. 外部方法成功者按吸收审计流程范式卡化入库(下次库内就有)

### 3.3 轨迹留档(加分材料)

`metric_trajectory.json` 每轮记录: 轮次/子问题/方案变更/指标前值后值/诊断深度/耗时。
Gloom在"诚实性声明"小节用轨迹写**方法学洞察**: "方案A(RSM)在θ*上R²_test=0.42 → 诊断: 三维效应标量参数不足 → 换GPR+标准化 → 0.991"。实战评审把这类轨迹列为加分点。

## §4 与门禁的接法

- M-Loop 发生在 **P1 与 C1 之间**(P1 最小可运行确认后、全量出图前)
- C1 新增 D6 维度: 读 `model_quality_score.json`, 硬指标存在不达标项 → C1 返回 FAIL(附不达标清单); 全部达标 → D6 PASS; 轨迹存在但收敛于 ②③(预算尽/无改善) → D6 WARN(诚实披露后可放行)
- 迭代期间不允许进入 P2 冻结

## §5 四层方案评审(自研四层: 证据—论证—表达—合规, Linger自审用)

Linger提交/修订方案前, 四层自审:

1. **证据层**: 每个模型选择有题目特征/文献/数据依据(可追溯, 非"常用")
2. **论证层**: 指标目标卡的阈值有辩护来源
3. **合同层**: 握手包变量/伪代码/约束可直接翻译, 无"适当调整"
4. **格式层**: 产物格式符合固定产物规范

## §6 防自欺条款

- 禁止为达标更换验证口径(CV 方案/对比基准事后改)
- 禁止把训练集指标写进轨迹当改善证据(坑2)
- 轨迹只记真实运行结果; 模拟/手填指标 = 坑7 同级违规
- 迭代失败的路线同样入论文(方法失败史), 藏失败 = 评委发现即重创
