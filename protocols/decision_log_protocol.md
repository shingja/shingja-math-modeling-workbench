## 一、核心原则

建模过程中的每个**关键决策**必须有记录。决策日志是:
- **跨Session的连续记忆**: 下一Session启动时自动加载
- **回退的依据**: 决策X导致问题 → 回退到决策X-1
- **论文"模型选择"章节的素材**: 每个决策有理由、有对比、有出处

## 二、decision_log.json 格式

```json
{
  "project": "T01",
  "decisions": [
    {
      "id": "D001",
      "phase": "MODELER",
      "timestamp": "2026-07-29T16:20:00",
      "question": "Q1链约束求解方法",
      "options": [
        {"id": "A", "method": "Brent二分法", "pros": "无条件收敛", "cons": "每次迭代需评估目标函数"},
        {"id": "B", "method": "牛顿法", "pros": "收敛速度更快", "cons": "需导数, 大θ时不稳定"}
      ],
      "choice": "A",
      "reason": "Brent二分法保证单调收敛, 不依赖导数, 适合224个把手的大规模链式求解",
      "impact": "影响Q1-Q3的求解精度和稳定性"
    }
  ]
}
```

## 三、必须记录的决策类型

| 决策类型 | 何时记录 | 示例 |
|------|------|------|
| 算法选型 | Linger阶段 | Brent vs 牛顿 vs fsolve |
| 参数选择 | Linger/Tide | k=8 vs k=3, PSO种群=50 |
| 模型修正 | 联合校准 | 碰撞检测修复(板头+27.5cm) |
| 数据预处理 | Linger | 缺失值=检出限/2 |
| 入口策略 | Linger | frac=0.98 vs frac=1.0 |
| 论文路线 | Gloom | A016路线 vs A053路线 |

## 四、决策影响追溯

每个决策标注:
- **直接影响**: 该决策改变的数值/结果
- **下游传播**: 影响哪些后续决策或子问题
- **备选方案**: 未选择的方案及其后果

示例 (T01 D003):
```
决策: Q4入口策略 frac=0.98
直接影响: S曲线总长 14.14→13.85m
下游传播: Q5 v_max 1.522→1.449m/s (偏差22%→3%)
备选方案: frac=1.0 (更保守, v_max更大), frac=0.85 (更激进, S曲线更短)
```

## 五、与 manifest.json 的分工

- **manifest.json**: 状态机 (哪个阶段、什么状态、阻塞原因)
- **decision_log.json**: 决策记录 (选了什么、为什么、影响如何)
- **frozen_numbers.json**: 数值快照 (数值是什么、来源哪里)

三者互补, 构成完整的项目记忆。
