> 解决: M-Loop 库内模型组合无法达标时, 向外搜索全网方法引入新模型。
> 策略: **只检不禁**——搜索本身不设禁区(赛题级讨论/解答同样是高效解题参照), 以检查项保证搜索效果与结果最优; 合规要求只落在最终声明侧(论文/AI使用详情/参考文献), 不在搜索环节设门禁。

## §1 触发条件

1. M-Loop 库内迭代 ≥2 轮无显著改善(改善 <2%)
2. 或Linger判定库内无匹配模型族(题型/数据形态与全部范式卡不匹配)
3. 或用户明确要求引入外部方法

触发后按本协议执行, 完成后回到 M-Loop 迭代链。

## §2 检查清单(只检不禁, 搜索完成后逐项核对)

### 2.1 搜索覆盖检查(搜得全不全)

- [ ] 学术层: 方法论文/综述/基准是否已搜(arXiv/Google Scholar/OpenAlex/知网/万方)
- [ ] 开源层: 可运行实现是否已搜(GitHub 代码搜索/papers-with-code)
- [ ] 平台层: 赛题相关讨论与解答是否已搜(题号+题名关键词, CSDN/知乎/GitCode/博客园/小红书/面包多)——**这是最高效的解题参照路径, 应当主动搜**
- [ ] 数学层: 数学工具/数值方法是否已搜(Wolfram MathWorld/Math StackExchange/教材)
- [ ] 对照: 其他队伍/公开方案的做法与结果是否已搜(题号直接搜, 记录其方法路线与关键指标)

### 2.2 效果检查(搜到的值不值得用)

- [ ] 找到的方案 vs 库内方案: 指标对比(预期改善幅度)? 实现成本? 失败风险?
- [ ] 候选卡齐全: 方法名/来源/核心思想/与库内差异/适用性/实现成本/失败风险
- [ ] 外部方案指标与我方现有指标对比: 我方更强→记录优势证据(答辩防御用); 我方更弱→分析差距根因并吸收其方法

### 2.3 结果更优检查(最终目标)

- [ ] 引入后重跑 model_quality_score: 指标是否提升? 是否达标?
- [ ] 与搜到的其他队伍方案对比: 我方结果是否更优/更有说服力?(对比表留档)
- [ ] 若不如他人: 差距根因是否诊断清楚(方法/数据/实现)? 可吸收的点是否已吸收?

### 2.4 风险提示(提示, 不阻止; 由队员自行决策)

- 直接照抄他人论文/代码 → 参赛规则第4条, 可能取消评奖资格: 建议理解后改造 + 文献引用
- 赛题讨论中的解答直接搬用 → 查重风险: 建议按方法论重构
- **声明义务(必须做, 这是合规底线)**: 用到的 AI 工具与外部资料, 在论文(参考文献/正文标注)与 AI 工具使用详情中如实声明——声明是义务, 搜索不是禁令

## §3 搜索分层(按序执行, 每层 ≤45 分钟)

| 层 | 渠道 | 找什么 | 工具 |
|---|---|---|---|
| 1 学术层 | arXiv / Google Scholar / OpenAlex / 知网 / 万方 / Crossref | 方法论文、综述、基准 | `tools/paper_search` / `modules/shingja-mathmodeling-search.md` / WebSearch |
| 2 开源层 | GitHub 代码搜索 / papers-with-code | 可运行实现、算法细节 | WebSearch + 仓库 clone 后本地改造 |
| 3 平台层(含赛题级) | CSDN / 知乎 / GitCode / 博客园 / 小红书 / 面包多 | 赛题讨论与解答、实现技巧、工程避坑 | WebSearch(题号+题名关键词, 也搜方法论关键词) |
| 4 数学层 | Wolfram MathWorld / Math StackExchange / 数学教材 / 司守奎教材 | 数学工具、定理、数值方法 | WebSearch + 本地教材库 |

## §4 产出: 新方法候选卡

每找到 1 个候选方法(库外来源), 输出一条:

| 字段 | 内容 |
|---|---|
| 方法名 | 如 Physics-Informed Neural Network |
| 来源 | 文献 DOI/arXiv ID/仓库 URL/平台链接(可追溯) |
| 核心思想 | 2-3 句 |
| 与库内方法差异 | 为什么库内 161 卡覆盖不了 |
| 适用性论证 | 与本题数据维度/规模/约束的匹配分析 |
| 实现成本 | 依赖/计算量/编码量 高/中/低 |
| 失败风险 | 数据量不足/超参敏感/不可解释 等 |

写入 `PROJECT_ROOT/外部方法候选.md`, 交Linger评审后决定引入。

## §5 引入新方法的流程

1. Linger评审候选卡(适用性/成本/风险)→ 选中 → 更新题目分析报告与握手包
2. Tide实现(改造为 skill 风格, 注明来源; 数值卫生 15 条照跑)
3. 重跑 model_quality_score → 达标/不达标继续 M-Loop
4. 达标且评审确认通用价值 → 按吸收审计流程(absorption_audit)范式卡化入库, 下次库内就有

## §6 方案对比终局(全部尝试后的兜底)

当 M-Loop 预算耗尽仍未达最高标准:

1. 汇总**所有**已尝试方案与结果(含失败方案、含外部搜到的方案)→ `PROJECT_ROOT/方案对比表.md`:

| 方案 | 来源(库内/外部+文献) | 关键指标1 | 指标2 | 复杂度 | 风险 | 结论 |
|---|---|---|---|---|---|---|
| 方案A | 库内 PARADIGM-1003 | ... | ... | 低 | 低 | 落选: 指标不足 |
| 方案B | 外部 PINN (arXiv:...) | ... | ... | 高 | 中 | **最终采用** |

2. 取指标最优且综合风险可接受者为最终方案
3. 其余方案转为论文的**辅助证明与对比分析节**(写法模板见 诚实披露协议 §六)
4. 与搜到的其他队伍方案对比: 我方更优 → 写进对比节的"相对优势"论证(外部对标协议 §四防御话术); 我方更弱 → 差距根因入局限章

## §7 预算

- 搜索层每层 ≤45 分钟; 外部方法引入 ≤2 个(引入太多=方案发散, 论文写不清)
- 总预算与 M-Loop 共用: 剩余小时 ×1; 超时强制进入 §6 对比终局

## §8 声明义务(搜索完成后的必做事项, 非搜索门禁)

1. 论文参考文献: 引用用到的外部方法文献(DOI); AI 工具列最后一条
2. 正文标注: 外部方法来源在相应位置标注
3. AI 工具使用详情: 如实记录搜索用到的 AI 工具与交互(模板见 lessons/AI工具使用详情模板.md)
4. 方案对比表.md 与论文对比节数值一致
